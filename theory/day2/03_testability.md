## Флип: Какой код тестируемый?
- immutable объекты
- разделение Command / Query
- маленькие модули
- низкая связность
- единая ответственность модуля
- Закон Деметры: "разговаривайте со своими друзьями, а не с незнакомцами"
  - Собака().хвост().помахать() vs Собака.показать_радость() и показать_радость(): хвост().помахать()
  
![law Demeter](assets/law_Demeter.png)
  
- Заменяйте ifs/switch полиморфизмом
- DI (dependency injection) все зависимости передаются извне
  - Конструктор (постоянная зависимость, жизненный цикл длительный)
  - Свойство
  - Параметр (жизненный цикл короткий)
- детерминированность, код выдает одинаковый результат (постоянное - в конструктор, транзиентное - в параметр)

## Seam, peel, slice
![Legend](assets/ut-tdd-legend.png)

### Флип: Peel
Выносим чистую логику внутрь отдельной функции, «отшелушивая» зависимости наружу.

![Peel](assets/ut-tdd-peel.png)

### Флип: Slice
Разрезаем по слою зависимости и подставляем test double на её место.

![Slice](assets/ut-tdd-slice.png)

### Флип: Наследование для создания Seam
Создаём шов через наследование: переопределяем (override) зависимый метод в подклассе и подставляем stub.

![Seam](assets/ut-tdd-seam.png)

Seam - шов. Нередко это используется как общее название подобных подходов. То есть и с помощью peel и с помощью slice мы по сути создаём "швы" в коде.
