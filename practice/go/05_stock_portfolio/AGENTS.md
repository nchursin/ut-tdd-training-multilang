## Рабочий процесс (ATDD/TDD)

1. Сначала напишите один компилирующийся acceptance test на Go и запустите `go test ./...`: он должен падать из-за отсутствующей логики, а не из-за ошибки компиляции.
2. После согласования acceptance test переходите к маленьким unit-тестам. Для каждого цикла: один красный тест → минимальная реализация → зелёный тест → рефакторинг.
3. Не дублируйте acceptance-сценарий unit-тестами. Unit-тесты проверяют отдельные типы и методы напрямую.
4. Не добавляйте поля, конструкторы или логику в RED; допустимы только типы и сигнатуры с безопасным неверным значением.
5. После каждого этапа запрашивайте согласование пользователя. В конце выполните `go test ./...`.

Используйте обычный Go table-driven style с `t.Run` для трёх и более однотипных случаев.
